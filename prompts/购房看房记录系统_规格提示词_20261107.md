# 购房看房记录追踪系统 —— 实现规格提示词

你是一名全栈工程师。请基于以下规格实现一个**面向个人购房者的看房记录与对比 Web 应用**。本规格既可用于从零搭建，也可作为对齐现有实现、继续迭代的依据。请严格遵循「技术栈与架构约束」，不要擅自更换技术选型。

---

## 一、项目目标
帮个人购房者：
1. 记录每一次看过的房子（户型、价格、面积、地段、图片等）；
2. 在地图上直观看到所有看房点的分布；
3. 多套房源并排对比，辅助决策；
4. 跟踪每套房源的跟进进度（带看、议价、中介反馈等日志）；
5. 沉淀购房知识（内置科普文章 + 个人上传的资料/笔记）。
数据全部存本地 PostgreSQL，支持多账号注册登录，且**不同账号数据互相隔离**。

## 二、技术栈与架构约束（必须遵守）
- **后端**：Node.js **原生 `http` 模块**（不要用 Express / Koa 等框架）+ `pg` 驱动直连 PostgreSQL。所有路由、鉴权、自动建表都写在单一 `server.js` 里。
- **前端**：零构建的**原生 HTML + CSS + JavaScript**（不要用 React / Vue / Vite / TypeScript 构建）。静态资源放 `public/`。外部库只允许通过 CDN `<script>` 引入（如高德地图 JS API）。
- **数据库**：PostgreSQL（建议库名 `house_view`，角色 `hvt`）。`server.js` 启动时自动 `CREATE TABLE IF NOT EXISTS` 建表，无需手工初始化。
- **鉴权**：邮箱 + 密码注册/登录，签发 **Bearer Token**（JWT 或自研 token 均可）。所有业务接口校验请求头 `Authorization: Bearer <token>`；后端按当前登录用户注入 `owner_id`，前端既不传也不信任 `owner_id`。
- **运行约定**：默认端口 **8787**，`npm start` 即 `node server.js` 启动，服务由使用者自己管理（AI 不要自动占用 8787 端口）。每次改前端静态文件，要在 `index.html` 的资源引用上加 `?v=版本号` 以避免浏览器缓存旧文件。

## 三、数据模型（PostgreSQL）
1. **users**：`id, email(唯一), password(哈希), name, avatar, phone, created_at`
2. **properties（房源）**：`id, owner_id, title, price, layout(户型), area(面积), address, district(区域), community(小区), floor, total_floor, orientation(朝向), decoration(装修), year(建成年份), contact(联系人), phone, note(备注), images(JSON 图集/封面), lng, lat(经纬度), favorite(布尔), deleted_at(软删除标记), created_at, updated_at` —— 删除先置 `deleted_at`，进回收站，可恢复或彻底删除。
3. **property_followups（跟进日志）**：`id, property_id, owner_id, content, created_at` —— 一套房源可有多条，按时间倒序展示。
4. **knowledge_files（知识资料）**：`id, owner_id, title, filename, stored_path(服务器路径), mime, size, kind('file'|'note'), content(笔记正文，仅 note 用), created_at` —— 仅当前用户可见；文件落盘到 `uploads/knowledge/{owner_id}/`，单文件上限 30MB。

## 四、后端 REST 接口清单
- `POST /api/auth/register` `{email,password}` → `{token,user}`
- `POST /api/auth/login` `{email,password}` → `{token,user}`
- `GET  /api/auth/me` → 当前用户
- `PATCH /api/auth/me` `{name,avatar,phone...}` → 更新个人资料
- `POST /api/auth/logout`
- `GET    /api/properties` → 当前用户全部房源（不含已删）
- `POST   /api/properties` `{row}` → 新增
- `GET    /api/properties/:id` → 单条详情
- `PUT    /api/properties/:id` `{row}` → 编辑
- `DELETE /api/properties/:id` → 软删除（进回收站）
- `POST   /api/properties/:id/restore` → 从回收站恢复
- `POST   /api/properties/:id/purge` → 彻底删除
- `POST   /api/properties/:id/favorite` `{favorite:bool}` → 收藏/取消
- `GET    /api/properties/:id/followups` → 跟进列表
- `POST   /api/properties/:id/followups` `{content}` → 新增跟进
- `DELETE /api/properties/:id/followups/:fid` → 删除某条跟进
- `GET    /api/trash` → 当前用户已软删房源列表
- `POST   /api/upload` `{dataUrl}` → 头像上传，返回 `{url}`
- `GET    /api/knowledge` → 当前用户资料列表（仅自己）
- `POST   /api/knowledge` 两种用法：① `{kind:'note',title,content}` 建笔记（不落盘文件）；② `{dataUrl,filename,title}` 上传文件
- `GET    /api/knowledge/:id/file` → 鉴权下载（响应头 `Content-Disposition: attachment`）
- `DELETE /api/knowledge/:id` → 删除资料（同时删服务器文件）

约定：成功响应体 `{data:...}`，失败 `{error:'消息'}`，并用正确 HTTP 状态码（401/404/500 等）。

## 五、前端页面与功能（侧栏 6 个视图）
1. **房源列表 `list`**：卡片流（封面图 + 标题/价格/户型/面积/地址摘要）；工具栏支持「只看收藏」筛选；每张卡片操作区「编辑 / 删除 / 更多▾」下拉含「复制」「收藏」；支持新增、编辑、删除（软删）。
2. **地图分布 `map`**：用高德地图 JS API，根据房源地址做地理编码得到经纬度并打点标注；点击标点可看房源概要。
3. **房源对比 `compare`**：勾选多套房源并排对比关键字段（价格/面积/户型/地段等）。
4. **回收站 `trash`**：列出已删房源，可单条恢复或彻底删除。
5. **购房知识 `knowledge`**：
   - 顶部「＋新建/上传资料」按钮 → 选择面板（上传文件 / 新建笔记）；
   - 内置 8 篇购房科普文章（`knowledge-data.js` 里的 `window.KNOWLEDGE_ARTICLES`，全账号共享，不入库）；
   - 用户上传的文件与自建笔记入库且按账号隔离；
   - 点文章/资料 → 右侧滑出阅读器（占屏约 70%）；
   - 文件可下载（鉴权）、可删除。
6. **设置 `profile`**：主题切换（极浅 / 深色两套）、个人资料编辑（昵称/头像/电话等，左侧信息栏宽度可调）。

## 六、UI / UX 规范
- 设计令牌化：CSS 变量集中在 `tokens.css`；两套主题（极浅为默认、深色）通过根节点 class 切换。
- 卡片式房源列表：封面图圆角 + 卡片正文区；下拉菜单需不被卡片 `overflow:hidden` 裁切（下拉用 `visible` 或浮层）。
- 跟进日志用右侧滑出抽屉，内部为纵向时间轴；抽屉 `z-index` 必须高于地图浮层，避免被遮挡。
- 响应式：移动端（≤760px）左右分栏布局自动堆叠为上下排列。
- 登录/注册页采用左右分栏（一侧展示看房主题视觉，一侧表单）。

## 七、已实现范围（最小可用标准 / 验收基线）
房源增删改查、收藏与「只看收藏」、回收站（软删/恢复/彻底删）、跟进日志（右侧抽屉 + 时间轴）、批量导入与一键示例数据、地图分布（高德自动标注）、房源对比、购房知识页（内置 8 篇共享文章 + 用户上传/下载 + 笔记 + 右侧阅读器 70%）、设置（主题/个人信息）、注册登录与多账号隔离、头像上传。

## 八、验收要点
1. 注册两个账号，互相看不到对方任何房源 / 知识资料（owner 隔离生效）。
2. 上传任意 ≤30MB 文件后可下载，且内容一致；新建笔记可查看与删除。
3. 删除房源进入回收站，可恢复、可彻底删除；彻底删除后不可见。
4. 跟进记录按时间倒序展示，可添加与删除。
5. 切换深色 / 极浅主题全局生效；移动端布局正确堆叠。
6. 前端改动加 `?v=` 版本号后，刷新即生效（无缓存残留）。
